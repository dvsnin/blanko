# Blanko: правила для Claude Code

Интерактивная доска для детского сада. Коробочный продукт: один экземпляр на один сад, одна `organization` в БД. Кабинет для педагога, доски открываются на интерактивной панели группы, детских аккаунтов нет.

## Текст и код

- Только короткие дефисы `-`. Никаких длинных тире `—`, `–` и стрелок `→ ← ↔` ни в коде, ни в комментариях, ни в UI-копии. В логах и комментариях направление пишется как `->`.
- Комментарии короткие и только по делу: что неочевидно или почему так решено. Не описывать то, что видно из кода, не оставлять «шапки» на пять строк. Пометки на будущее в виде `TODO(collab): ...`.
- UI на русском, в коде и API сущности на английском: группа в интерфейсе это `team` в коде и БД, не переименовывать.
- Роли в интерфейсе: «Администратор» и «Пользователь». Слово «сад» в интерфейсе не используется, название организации приходит с бэкенда и показывается в топбаре вместо бренда.
- Дизайн: токены в `frontend/dashboard/src/app.css`, шрифт Nunito, базовые классы `.btn`, `.btn--soft`, `.btn--ghost`, `.chip`, `.input`. Звезда избранного через `StarToggle`, меню «⋯» через `MenuButton`, у всех карточек одинаково: звезда и «⋯» в правом верхнем углу обложки, меню закрывается при уходе курсора с карточки.

## Тесты

- Бэкенд: только интеграционные табличные тесты на хендлеры, один хендлер равно один тест с тест-кейсами. Юнит-тесты на сервисы, репозитории и чистые функции не писать.
- Фронтенд: vitest на чистые функции в `utils` и на ключевое поведение страниц через провайдеры контекстов. Тривиальные тесты не нужны. Фикстуры в отдельных файлах (`*.fixture.ts`), не в тестах.
- `tsc --noEmit` в дашборде показывает старые ошибки в нетипизированных компонентах; важно только не добавлять новых.

## Данные и бэкенд

- Миграции: SQL в `backend/app/migration` с goose-аннотациями, применяет сам бэкенд при старте. Комментарии `COMMENT ON` на каждую таблицу и колонку обязательны. Данные, вставляемые миграцией, с `ON CONFLICT DO NOTHING`, чтобы правки сада переживали обновление.
- INSERT через squirrel: при добавлении колонки менять и `Columns`, и `Values`, иначе «INSERT has more target columns than expressions».
- Права проверяются в сервисе в одном месте (например `canEditTemplate`, `boardAccess`), фронтенд только читает флаги из DTO (`canEdit`) и прячет кнопки. У доски два права: управлять (`canEditBoard`: создатель, owner/admin группы) и работать с содержимым (`boardAccess`: edit/view/deny по `team_access`, `link_access_enabled` даёт view не участникам, админ организации всегда edit).
- Админы задаются при установке в `deploy/.env` (`APP_ADMIN_EMAILS`, `APP_ORG_NAME`), bootstrap при старте выставляет роли. Первый адрес становится владельцем один раз.
- Сортировка по-русски делается в Go, не ICU-коллацией БД.
- Содержимое канваса живёт в S3-совместимом хранилище (RustFS в compose) под префиксом документа `boards/{id}/` или `templates/{id}/`; канвас держит вебсокет `/app/ws/{kind}/{id}`, комната в `internal/doc` рассылает диффы остальным подключениям сразу и пишет снапшот раз в секунду. Ссылка на картинку в документе `asset:<ключ в bucket>`. Копирование документа это копирование префикса плюс переписывание этих ссылок (`DocumentService.Copy`).
- Тесты бэкенда ходят в Postgres из `TEST_POSTGRES_DSN` (отдельная база `app_test`), без переменной скипаются: `make test-backend`. E2E канваса и дашборда через headless Chrome: `docs/tools/*.mjs`.
- Счётчики на экранах пока клиентские; при курсорной пагинации списков сервер отдаст агрегаты одним запросом.

## Стенд и процесс

- `make up` собирает фронтенд, пересобирает бэкенд и перезапускает контейнеры; `make up SKIP_FRONTEND=1` только бэкенд. Статика фронтенда запекается в образ, после правок фронта нужен полный `make up`.
- Секреты в `deploy/.env`, не печатать. psql: `docker exec deploy-postgres_backend-1 psql -U $APP_POSTGRES_USER -d $APP_POSTGRES_DB`.
- tldraw закреплён на 3.15.3 (бесключевой режим с watermark). Апгрейд только с действующим `TLDRAW_LICENSE_KEY`, watermark скрывать нельзя.
- Визуальная проверка на живом стенде: `node docs/tools/dashboard-shots.mjs <папка>` логинится тестовым пользователем в headless Chrome и снимает сетку, список, шаблоны и группы (флаги `ACCESS=1`, `MEMBERS=1`, `MENU=1` открывают диалоги и меню); E2E канваса `docs/tools/canvas-e2e.mjs <publicId>` с `MEDIA=1`, `RESTART=1`, `SHOT=путь`.
- Перед пушем ветка схлопывается в один коммит с коротким сообщением на английском, например `Dashboard redesign: templates, admin role, card polish`. Пуш и слияние делает пользователь.
- `docs/` в `.gitignore`: спецификации и планы локальные, в коммиты не попадают.
