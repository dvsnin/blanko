# Blanko

Веб-приложение с интерактивной доской: бесконечный холст для рисования и визуальной работы с материалом.

## Принцип работы

Содержимое доски живёт на сервере. Педагог открывает доску на своём компьютере, та же доска открыта на интерактивной панели группы: всё, что рисует педагог, сразу появляется на панели, а дети рисуют на панели пальцем или стилусом. Канвас держит вебсокет с бэкендом, снапшот записывается в хранилище раз в секунду и при остановке сервера.

## Реализовано

- **Доска** - бесконечный холст: рисование от руки, фигуры, стрелки, текст, стикеры, изображения, зум и панорамирование; содержимое и картинки хранятся на сервере, доска открывается с любого устройства.
- **Кабинет** - доски группы сеткой или списком, избранное, настройки профиля; выбранная группа, вид, фильтр и сортировка запоминаются на аккаунте.
- **Шаблоны** - больше ста готовых занятий по двенадцати темам (счёт, грамота, окружающий мир, речь, логика, рисование, сенсорика, режим дня, музыка, здоровье, безопасность, эмоции) с заданиями на холсте; свои шаблоны из любой доски.
- **Группы** - доски разложены по группам детского сада; у группы возраст, воспитатели и участники, которых добавляют из справочника сада или приглашают по почте.
- **Доступ** - уровень доступа участников задаётся в настройках группы и наследуется всеми её досками; у отдельной доски его можно переопределить или вернуть «как в группе». Доску можно открыть по ссылке всем вошедшим для просмотра, дублировать и перенести в другую группу.
- **Присутствие** - на доске видны курсоры и выделение других участников, по клику на участника панель следует за ним.
- **Вход** - через Keycloak (OIDC) по e-mail; страницы входа на русском и в оформлении кабинета.
- **Роли** - первые админы сада задаются при установке переменной `APP_ADMIN_EMAILS` в `deploy/.env` (через запятую); дальше администратор назначает и снимает других администраторов в разделе «Участники сада», у сада всегда остаётся хотя бы один. Админы видят и правят всё, остальные воспитатели только своё. Название сада в `APP_ORG_NAME`.

## Стек

| Слой | Технологии |
|---|---|
| Дашборд | React 19, TypeScript, Vite |
| Холст | [tldraw](https://tldraw.dev) 3.15.3 (бесключевой режим с watermark), собран в статику вместе с ресурсами, интернет не нужен |
| Backend | Go 1.25, gorilla/mux, gorilla/websocket, pgx, aws-sdk-go-v2 |
| База данных | PostgreSQL 17 |
| Хранилище содержимого | RustFS (S3-совместимое) |
| Вход и маршрутизация | Keycloak 26, oauth2-proxy, Traefik |
| Запуск | Docker Compose |

## Быстрый старт

Нужны Docker с Compose v2, pnpm 10 и Node.js 20+.

```sh
git clone git@github.com:dvsnin/blanko.git
cd blanko
make up
```

Команда соберёт фронтенд, поднимет контейнеры и применит миграции. Открыть **http://localhost/app/dashboard** и войти:

```
логин:  test@example.com
пароль: qwerty1234
```

Должен открыться кабинет - в нём можно создать группу и доску, открыть её и порисовать.

```sh
make down                                            # остановить
make up SKIP_FRONTEND=1                              # перезапустить без пересборки фронта
docker compose -f deploy/docker-compose.yml down -v  # остановить и стереть данные
```

> Кабинет на `http://localhost`, Keycloak на `http://localhost:8081` (консоль администратора там же). Правок hosts-файла не нужно; по IP или имени машины в локальной сети кабинет тоже откроется.

## Структура

```
frontend/dashboard/    # React-приложение кабинета
frontend/canvas/       # логика холста на tldraw, собирается Vite в backend/app/static/canvas/assets
backend/app/           # Go-сервис: API, вебсокет комнат, рендер страниц, статика
  internal/            #   handler, service, repository, doc (комнаты), storage
  migration/           #   SQL-миграции
  static/canvas/       #   страница холста: разметка и стили шапки, сборка из frontend/canvas в assets/
  static/fonts/        #   Nunito для кабинета и холста, работает без интернета
deploy/                # docker-compose, realm и тема Keycloak, .env.example
```

## Конфигурация

Параметры стенда лежат в `deploy/.env`, он не хранится в Git. `make up` создаёт его из `deploy/.env.example` - там же описаны все переменные.

Значения по умолчанию рассчитаны на локальный запуск. Для публичного развёртывания их нужно заменить: пароли БД, учётную запись Keycloak, ключи хранилища, `OAUTH2_PROXY_COOKIE_SECRET` и `OIDC_CLIENT_SECRET`. Там же задаётся `TLDRAW_LICENSE_KEY` - см. «Лицензия».

## Данные

Схему создают миграции из `backend/app/migration/`. Они применяются автоматически при старте бэкенда - отдельной команды не нужно. Отключаются переменной `RUN_MIGRATIONS=false`.

Содержимое досок и шаблонов и картинки лежат в S3-совместимом хранилище (в compose это RustFS) под префиксом документа: `boards/<id>/`, `templates/<id>/`. В Postgres только метаданные. Удалённые доски и шаблоны вычищаются из хранилища через 30 дней.

Тестовый пользователь приходит из `deploy/keycloak/realm-blanko.json`, запись в БД создаётся при первом входе. На уже поднятом стенде realm повторно не импортируется: настройки меняются через `kcadm.sh` в контейнере или сбросом `down -v`.

## Разработка

```sh
pnpm --filter @blanko/dashboard dev    # Vite с HMR на :5173
pnpm --filter @blanko/dashboard build  # сборка в backend/app/static/dashboard
pnpm --filter @blanko/canvas build     # сборка холста в backend/app/static/canvas/assets
cd backend/app && go build ./...       # сборка бэкенда
```

Dev-сервер Vite отдаёт только вёрстку: данные пользователя инжектит бэкенд при рендере страницы, а запросы к API требуют сессии. Дашборд с данными проверяется через `make up`.

Тесты бэкенда интеграционные, им нужен Postgres стенда и отдельная база `app_test`:

```sh
docker exec deploy-postgres_backend-1 psql -U <APP_POSTGRES_USER> -d <APP_POSTGRES_DB> -c 'create database app_test'
make test-backend                      # DSN собирается из deploy/.env
pnpm --filter @blanko/dashboard exec vitest run
```

Холст собирается из `frontend/canvas/src/main.js` командой выше; после изменений нужна пересборка образа - статика копируется на этапе build. Кабинет, холст и страница входа не ходят в интернет: tldraw, React и шрифты лежат в статике.

## Ограничения

- Один экземпляр бэкенда: комнаты досок живут в его памяти, рассылка между несколькими экземплярами не делается.
- На одной панели в один момент рисует один человек: tldraw один редактор на устройство, два касания он трактует как жест масштабирования.
- В фоновой вкладке браузера изменения не отправляются, пока вкладка не станет активной.
- Запуск только локальный, по HTTP, без production-конфигурации.

## План дальнейших действий

- CI: сборка, линтеры и прогон тестов на каждый pull request.
- Описание API: спецификация OpenAPI для эндпоинтов бэкенда.
- «Корзина»: восстановление удалённых досок и шаблонов в течение 30 дней.
- Вход панели группы без пароля: отдельный ключ устройства вместо учётной записи в Keycloak.
- Production-конфигурация: HTTPS, внешний домен, секреты и tldraw-лицензия для публичного развёртывания.
