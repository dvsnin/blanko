# Blanko

Веб-приложение с интерактивной доской: бесконечный холст для рисования и визуальной работы с материалом.

## Принцип работы

Содержимое доски живёт на сервере. Педагог открывает доску на своём компьютере, та же доска открыта на интерактивной панели группы: всё, что рисует педагог, появляется на панели, а дети рисуют на панели пальцем или стилусом. Канвас держит вебсокет с бэкендом, изменения пересылаются между подключениями сразу, снапшот записывается в хранилище раз в секунду и при остановке сервера.

## Реализовано

- **Доска** - бесконечный холст: рисование от руки, фигуры, стрелки, текст, стикеры, изображения, зум и панорамирование.
- **Дашборд** - список досок, избранное, переключение вида, настройки профиля.
- **Разделы** - доски разложены по «командам»: способ группировать доски.
- **Вход** - через Keycloak (OIDC), доски привязаны к аккаунту.
- **Роли** - админы сада задаются при установке переменной `APP_ADMIN_EMAILS` в `deploy/.env` (через запятую); они редактируют и удаляют любые шаблоны, остальные воспитатели только свои. Название сада в `APP_ORG_NAME`.
- **Содержимое и картинки на сервере** - доска открывается с любого устройства, доска из шаблона сразу содержит его рисунок, доску можно дублировать и перенести в другую группу, картинки лежат рядом с доской в хранилище.
- **Доступ к доске** - участники группы редактируют, только смотрят или не видят доску (настройка «Доступ» в меню доски); доску можно открыть по ссылке всем вошедшим только для просмотра. Создатель, владелец и админ группы и администратор сада видят и правят всё.

## Стек

| Слой | Технологии |
|---|---|
| Дашборд | React 19, TypeScript, Vite |
| Холст | [tldraw](https://tldraw.dev) 3.15.3 (бесключевой режим с watermark), подключён с CDN |
| Backend | Go 1.25, gorilla/mux, gorilla/websocket, pgx, aws-sdk-go-v2 |
| База данных | PostgreSQL 17 |
| Хранилище содержимого | RustFS (S3-совместимое), один bucket |
| Вход и маршрутизация | Keycloak 26, oauth2-proxy, Traefik |
| Запуск | Docker Compose |

## Быстрый старт

Нужны Docker с Compose v2, pnpm 10 и Node.js 20+.

```sh
git clone git@github.com:dvsnin/blanko.git
cd blanko
make up
```

Команда соберёт фронтенд, поднимет контейнеры и применит миграции. Открыть **http://blanko.localhost/app/dashboard** и войти:

```
логин:  test
пароль: qwerty1234
```

Должен открыться дашборд - на нём можно создать команду и доску, открыть её и порисовать.

```sh
make down                                            # остановить
make up SKIP_FRONTEND=1                              # перезапустить без пересборки фронта
docker compose -f deploy/docker-compose.yml down -v  # остановить и стереть данные
```

> Адрес именно `blanko.localhost`, а не `localhost` - по нему маршрутизирует Traefik. Если имя не резолвится (обычно на Windows), добавьте в hosts-файл `127.0.0.1 blanko.localhost keycloak.localhost`.

## Структура

```
frontend/dashboard/    # React-приложение: список досок
backend/app/           # Go-сервис: API, вебсокет комнат, рендер страниц, статика
  internal/doc/        #   комнаты документов: состояние в памяти, пересылка, запись снапшотов
  internal/storage/    #   S3-совместимое хранилище (и память для тестов)
  migration/           #   SQL-миграции
  static/canvas/       #   холст на tldraw (правится напрямую, без сборки)
deploy/                # docker-compose, конфигурация Keycloak, .env.example
```

## Конфигурация

Параметры стенда лежат в `deploy/.env`, он не хранится в Git. `make up` создаёт его из `deploy/.env.example` - там же описаны все переменные.

Значения по умолчанию рассчитаны на локальный запуск. Для публичного развёртывания их нужно заменить: пароли БД, учётную запись Keycloak, `OAUTH2_PROXY_COOKIE_SECRET` и `OIDC_CLIENT_SECRET`. Там же задаётся `TLDRAW_LICENSE_KEY` - см. «Лицензия».

## Хранилище

Содержимое досок и шаблонов и загруженные картинки лежат в S3-совместимом хранилище. В compose это RustFS (сервис `rustfs`, том `rustfsdata`), наружу он не публикуется. Ключи и bucket задаются в `deploy/.env`: `APP_S3_ACCESS_KEY`, `APP_S3_SECRET_KEY`, `APP_S3_BUCKET`. Bucket создаётся бэкендом при старте.

Раскладка: `boards/<id>/document.json` и `boards/<id>/media/<sha256>.<ext>`, для шаблонов то же под `templates/`. Всё, что нужно документу, лежит под его префиксом, поэтому копирование доски это копирование префикса, а перенос в другую группу хранилище не трогает. В Postgres хранятся только метаданные. `make down -v` стирает и хранилище.

Удалённые доски и шаблоны лежат в хранилище ещё 30 дней (`PURGE_AFTER`), затем фоновая задача бэкенда вычищает их объекты; окно оставлено под будущую «Корзину».

Бэкенд ходит в хранилище по S3 API через `aws-sdk-go-v2`, движок заменяется одной строкой образа в compose.

## База данных

Схему создают миграции из `backend/app/migration/`. Они применяются автоматически при старте бэкенда - отдельной команды не нужно. Отключаются переменной `RUN_MIGRATIONS=false`.

Тестовый пользователь приходит из `deploy/keycloak/realm-blanko.json`, запись в БД создаётся при первом входе. Сбросить состояние: `docker compose -f deploy/docker-compose.yml down -v`.

## Разработка

```sh
pnpm --filter @blanko/dashboard dev    # Vite с HMR на :5173
pnpm --filter @blanko/dashboard build  # сборка в backend/app/static/dashboard
cd backend/app && go build ./...       # сборка бэкенда
```

Dev-сервер Vite отдаёт только вёрстку: данные пользователя инжектит бэкенд при рендере страницы, а запросы к API требуют сессии. Дашборд с данными проверяется через `make up`.

Тесты бэкенда интеграционные, им нужен Postgres стенда и отдельная база `app_test`:

```sh
docker exec deploy-postgres_backend-1 psql -U <APP_POSTGRES_USER> -d <APP_POSTGRES_DB> -c 'create database app_test'
make test-backend                      # DSN собирается из deploy/.env
pnpm --filter @blanko/dashboard exec vitest run
```

Холст (`backend/app/static/canvas/index.html`) правится напрямую и сборки не требует, но после изменений нужна пересборка образа - статика копируется на этапе build.

## Ограничения

- Один экземпляр бэкенда: комнаты досок живут в его памяти, рассылка между несколькими экземплярами не делается.
- На одной панели в один момент рисует один человек: tldraw один редактор на устройство, два касания он трактует как жест масштабирования.
- Курсоры других участников и режим «панель следует за педагогом» пока не показываются.
- В фоновой вкладке браузера изменения не отправляются, пока вкладка не станет активной: так устроен `requestAnimationFrame`, на который опираются и tldraw, и канвас.
- Запуск только локальный, по HTTP, без production-конфигурации.
