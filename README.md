# Blanko

Веб-приложение с интерактивной доской: бесконечный холст для рисования и визуальной работы с материалом.

## Как это работает

Доска открывается в браузере и работает в рамках одной сессии: весь ввод идёт с компьютера, на котором она открыта – мышью, пером или касанием, если подключена интерактивная панель. Изображение при необходимости выводится на проектор или внешний монитор.

## Что есть

- **Доска** – бесконечный холст: рисование от руки, фигуры, стрелки, текст, стикеры, изображения, зум и панорамирование.
- **Дашборд** – список досок, избранное, переключение вида, настройки профиля.
- **Разделы** – доски разложены по «командам»: способ группировать доски.
- **Вход** – через Keycloak (OIDC), доски привязаны к аккаунту.

## Стек

| Слой | Технологии |
|---|---|
| Дашборд | React 19, TypeScript, Vite |
| Холст | [tldraw](https://tldraw.dev) 5.4, подключён с CDN |
| Backend | Go 1.25, gorilla/mux, pgx |
| Хранилище | PostgreSQL 17 |
| Вход и маршрутизация | Keycloak 26, oauth2-proxy, Traefik |
| Запуск | Docker Compose |

## Быстрый старт

Нужны Docker с Compose v2, pnpm 10 и Node.js 20+.

```sh
git clone git@github.com:dvsnin/blanko.git
cd blanko
make up
```

Команда соберёт фронтенд, поднимет контейнеры и применит миграции. Открыть **http://blanko.localhost/app/dashboard** и войти:

```
логин:  test
пароль: qwerty1234
```

Должен открыться дашборд – на нём можно создать команду и доску, открыть её и порисовать.

```sh
make down                                            # остановить
make up SKIP_FRONTEND=1                              # перезапустить без пересборки фронта
docker compose -f deploy/docker-compose.yml down -v  # остановить и стереть данные
```

> Адрес именно `blanko.localhost`, а не `localhost` – по нему маршрутизирует Traefik. Если имя не резолвится (обычно на Windows), добавьте в hosts-файл `127.0.0.1 blanko.localhost keycloak.localhost`.

## Структура

```
frontend/dashboard/    # React-приложение: список досок
backend/app/           # Go-сервис: API, рендер страниц, статика
  migration/           #   SQL-миграции
  static/canvas/       #   холст на tldraw (правится напрямую, без сборки)
deploy/                # docker-compose, конфигурация Keycloak, .env.example
```

## Конфигурация

Параметры стенда лежат в `deploy/.env`, он не хранится в Git. `make up` создаёт его из `deploy/.env.example` – там же описаны все переменные.

Значения по умолчанию рассчитаны на локальный запуск. Для публичного развёртывания их нужно заменить: пароли БД, учётную запись Keycloak, `OAUTH2_PROXY_COOKIE_SECRET` и `OIDC_CLIENT_SECRET`. Там же задаётся `TLDRAW_LICENSE_KEY` – см. «Лицензия».

## База данных

Схему создают миграции из `backend/app/migration/`. Они применяются автоматически при старте бэкенда – отдельной команды не нужно. Отключаются переменной `RUN_MIGRATIONS=false`.

Тестовый пользователь приходит из `deploy/keycloak/realm-blanko.json`, запись в БД создаётся при первом входе. Сбросить состояние: `docker compose -f deploy/docker-compose.yml down -v`.

## Разработка

```sh
pnpm --filter @blanko/dashboard dev    # Vite с HMR на :5173
pnpm --filter @blanko/dashboard build  # сборка в backend/app/static/dashboard
cd backend/app && go build ./...       # сборка бэкенда
```

Dev-сервер Vite отдаёт только вёрстку: данные пользователя инжектит бэкенд при рендере страницы, а запросы к API требуют сессии. Дашборд с данными проверяется через `make up`.

Холст (`backend/app/static/canvas/index.html`) правится напрямую и сборки не требует, но после изменений нужна пересборка образа – статика копируется на этапе build.

## Ограничения

- Нет совместного редактирования: доска пока не синхронизируется между устройствами.
- Нет автотестов, CI и описания API.
- Запуск только локальный, по HTTP, без production-конфигурации.
